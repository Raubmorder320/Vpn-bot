# Hamsterdam — self-hosted VPN с Telegram-ботом

Пет-проект: собственный VPN-сервер на Xray (VLESS + Reality) и Telegram-бот, который выдаёт доступ по инвайт-кодам и показывает трафик.
Работал на арендованном Linux VPS с апреля по сентябрь 2026; сейчас поднимается одной командой через Docker Compose.

## Архитектура

```
Telegram ──► bot (aiogram) ──HTTP──► api (FastAPI + SQLite) ──gRPC :10085──► xray (VLESS Reality :443) ◄── клиенты VPN
                                        │  пишет config.json ──────────────────────┘ (общий том ./xray)
                                        └─ читает базу vnstat хоста (/var/lib/vnstat, read-only)
```

| Сервис | Что делает |
|---|---|
| `xray` | VPN-сервер. Наружу открыт только порт 443. API Xray (`HandlerService`, `StatsService`) слушает 10085 внутри сети `vpn_net`. |
| `api` | Управляющий REST API: пользователи и инвайты в SQLite, генерация ключей Reality, vless-ссылки, учёт трафика. |
| `bot` | Интерфейс для пользователей и админа. Ходит только в `api`. |

## Как это работает

- **Первый запуск.** `api` копирует `xray/config.example.json` в `xray/config.json`, генерирует пару ключей Reality (`xray x25519`), кладёт приватный ключ в конфиг, а публичный — в `data/keys.json`. Только после этого (healthcheck + `depends_on: service_healthy`) стартует `xray`.
- **Новый пользователь.** API добавляет клиента в `config.json` (это постоянное состояние), проверяет конфиг (`xray -test`) и применяет его к работающему Xray через API (`xray api adu`) — **без перезапуска** и без разрыва соединений остальных пользователей.
- **Трафик.** Раз в 10 минут бот вызывает `/update_traffic_usage`. API забирает по gRPC счётчики `user>>>{email}>>>traffic>>>uplink/downlink` со сбросом (`reset=True`) и прибавляет их в БД. В начале месяца счётчики в БД обнуляются.
- **Общий трафик сервера** берётся из vnstat хоста: каталог `/var/lib/vnstat` монтируется в контейнер `api` только на чтение.

## Запуск

```bash
cp .env.example .env        # BOT_TOKEN, ADMIN_TELEGRAM_ID, SERVER_IP
docker compose up -d --build
```

Чтобы в админке работала статистика сервера, на хосте должен быть установлен vnstat: `sudo apt install vnstat`.

## Что проверено

На локальном стенде (Docker Compose) проверены:
- генерация ключей и запуск Xray;
- инвайт → регистрация → vless-ссылка;
- горячее добавление пользователя;
- подключение VLESS Reality клиентом;
- учёт трафика по пользователю.

С настоящим Telegram в этой версии бот не проверялся.

## Известные ограничения / что бы я улучшил

- API без аутентификации: защищён только тем, что не опубликован наружу (доступен лишь внутри `vpn_net`).
- Одно соединение SQLite на всё приложение — нормально для десятков пользователей, не для нагрузки.
- Пользователей нельзя удалить или отключить (нет `rmu`), `is_active` пока не используется.
- Лимит трафика (1000 ГБ) зашит в коде бота.
- Нет CI и тестов; следующий шаг — GitHub Actions (lint + сборка образов) и описание настройки VPS в Ansible.
